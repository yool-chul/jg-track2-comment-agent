## v1 → v2 변경 이유

- **v1 문제:** 운명원 문장이 같은 틀("운명원 연애사주 잘 본다던데 + 인연이 언제 올지")로 반복됨 → 75개를 만들면 한 사람이 쓴 티가 나고 '영상마다 다른가'에서 감점 위험. 운명원을 꺼내는 이유도 영상과 무관해 유도력이 약함
- **원인 추정:** 프롬프트에 예로 든 표현("잘 본다던데", "궁금해졌다")과 고정된 흐름("결국 인연과 타이밍은 알 수 없다는 마음")을 모델이 그대로 따름
- **v2 변경:** `hook` 단계를 추가해 운명원을 궁금해하는 이유를 영상의 고민(`worry`)에서 끌어내게 함 · 예시 표현 목록 제거 · '이미 쓴 댓글'의 운명원 표현도 피하게 함 · 과제 예시는 말투만 참고하도록 명시

## 남은 과제

- "운명원 연애사주로 ~ 알아보고 싶다" 틀이 새로 반복됨 (4/5) → 대량 생성 때 '이미 쓴 댓글' 목록으로 분산되는지 확인하고, 부족하면 문장 유사도 검사를 추가
- 자막 없는 라이브 영상은 설명란에 의존 → 목록에 '자막 없음' 표시, 시연에는 자막 있는 영상 사용
- 글자 수 해석: 과제 예시가 공백 포함 139자 · 공백 제외 104자 → **공백 포함 ≤ 120 & 공백 제외 ≥ 40**으로 검사해 두 해석을 모두 충족

## v3 — 자막 없는 영상은 장면 이미지로 (2026-10-16)

- **문제:** 테스트 영상(게임 인트로)은 자막이 꺼져 있고 설명도 비어 있어, 초안이 제목 한 단어("introStory")로만 만들어짐. 인기 댓글도 우리가 단 시험 댓글뿐이라 그걸 참고함
- **변경:** 자막이 없으면 유튜브 스토리보드(장면 미리보기, 키 불필요) 시트를 최대 6장 받아 Claude에 이미지로 함께 보냄 · `scene` 규칙에 "자막이 없으면 장면 이미지에 보이는 장면을 묘사" 추가 · 운명원이 들어간 댓글(우리가 단 댓글)은 인기 댓글 참고에서 제외
- **결과 (테스트 영상, 이미지 4장 · $0.047):** 짚은 장면이 "제목 'introStory'" → "노트 속 문 앞에 서 있던 고양이가 이후 텅 빈 옥상 구석에 혼자 한참 서 있는 장면"으로, 댓글도 그 장면과 '문'을 운명원 질문까지 이어 씀
- **한계:** 방송 직후의 라이브 영상은 일반 스토리보드가 아직 없어(라이브용 형식만 있음) 제목 · 설명으로 대체

## 실패와 개선 (PROCESS.md 재료)

1. **시스템 Python의 전역 패키지가 섞임** — 구버전 `brotli`가 임시 실행 환경에 섞여 SDK 응답 압축 해제 실패(`process() takes no keyword arguments`) → 프로젝트 전용 uv 가상환경(Python 3.12, 시스템 패키지 격리)으로 해결
2. **프롬프트 예시 표현의 복제** — 위 v1 → v2 참고
3. **자막 요청 IP 차단** — 시험 · 초안 생성으로 자막을 많이 요청하자 유튜브가 자막 요청을 일시 차단(`IpBlocked`). 코드가 이를 '자막 없음'으로 조용히 넘겨 자막 있는 영상도 제목 · 설명만으로 초안이 만들어짐 → 자막 상태를 ok · none · blocked로 구분해 기록하고 화면에 '자막 일시 차단'으로 표시, 차단 중에는 장면 이미지로 대체
